## 目的と制約

- シミュレーション上のロボットを用いた、1人用の3投カーリングゲームを作る。
- 既に投げた石を押し込むなどの戦略を使い、3個の石を中心へ集めることを楽しめるようにする。
- プレイヤーが投球を操作し、AIは予測によって判断を支援する。
- 氷の滑りやすさの変化と、その変化への適応を取り入れる。
- YouTubeのデモで、操作・ロボットの動作・結果・AIの役割が伝わるものにする。
- 実機購入やsim-to-realは行わない。
- ユーザーの作業時間は、提出準備を含めて最大20時間程度。
- 主成果は直交ロボット。多関節アームは、余力があれば比較対象として追加する。
- 課題PDF記載の締切は2026年11月2日（月）10:00。

## 合意したゲームの骨格

| 項目 | 要件 |
| --- | --- |
| 人数・形式 | 1人用。対戦機能は今回の対象から外す |
| 投球数 | 1ゲーム3投 |
| 投球済みの石 | 盤面に残し、後の投球との衝突で動く |
| 戦略 | 自分の石を押して中心へ寄せるなど、最終配置を考える |
| 採点時点 | 3投終了後、全ストーンが停止した時点 |
| 操作主体 | プレイヤーが方向と強さを指定し、ロボットが実行する |

## 得点

- 各ストーンの中心とハウス中心の距離に応じて点数を決める。
- 中心に一致する場合は100点。
- 中心から離れるほど直線的に減点する。
- ストーンがハウス外周にかかっている場合も、最低1点を与える。
- 完全にハウス外の場合は0点。
- 3投終了後の各ストーンの点数を合算する。投球直後の点数を固定して積み上げる方式にはしない。
- 距離に対する独自の加点方式であり、公式カーリングそのものの採点方式ではない。
- 境界にかかる区間の数式と、点数の端数処理は実装仕様で具体化する。

## 操作

- 方向と強さをスライダーで指定する。
- 回転は「左・なし・右」から選択する。
- 滑走中は、ボタンを押している間スイープする。
- プレイヤーの投球指示をAIが自動的に別の方向・強さへ変更する方式にはしない。
- 入力範囲、キー割り当て、投球開始位置は実装仕様で具体化する。

## AIと学習

### 基本機能

- 指定された投球に対し、予想軌跡と、衝突後を含む全ストーンの予想停止位置を表示する。
- 事前学習したモデルを使い、ゲーム中の投球結果で予測モデルを補正する。
- ゲーム中の補正はAIの予測の更新であり、人の入力を自動補正することを意味しない。

### 追加候補

- スイープした場合の変化やタイミングについて、AIが助言する。
- 自動スイープは採用済みの要件には含めない。

### 採用した設計

- AIが氷の状態を推定し、その推定を使った予測用シミュレーションで衝突・停止まで先読みする。
- 真の氷のパラメータや将来の変化を予測側に渡さず、観測から推定する。
- 未入力の将来のスイープ操作を先に知ることはできないため、予測が仮定する操作条件を明示する。
- 初投前は学習モデルの事前値を使う。滑走観測から氷を逐次補正し、予測表示を約0.4秒間隔で更新する。
- 衝突配置での評価と24ゲームの全体評価を実施した。詳細・限界は`poc_findings.md`に記録する。旧試作の数値を新ゲームの精度として使わない。

## 氷と物理の再現範囲

カーリングらしい操作と戦略を成立させる簡略モデルを使用する。

- 衝突：石同士が押し合い、移動・回転する。
- 回転・曲がり：回転方向に応じて曲がる効果を簡略モデルで扱う。
- スイープ：投球中の石の前方を掃き、到達距離や曲がり方に影響させる。
- 氷の変化：投球と投球の間で、リンク全体の滑りやすさを少し変える。
- 氷の融解や微細な表面構造まで計算するモデルは対象としない。

氷の変化量、カール・スイープの作用の強さ、衝突特性は、実装戦略と検証の段階で具体化する。

## 場外・リトライ・練習

以下も合意済みのゲームルールとする。

| 項目 | 要件 |
| --- | --- |
| 場外 | リンク外へ出た石は除外し、壁で跳ね返らせない。ハウス外でもリンク内の石は残す |
| リトライ | 氷を同じ初期条件に戻す。AIのゲーム中補正も初期状態に戻し、事前学習済みモデルから再挑戦する |
| 本番の試し打ち | すべて3投に数える。ゲーム内に無料の追加投球は設けない |
| 練習モード | 独立した練習モードは追加候補とし、基本機能には含めない |

## 実装仕様と検証で具体化すること

- 実装仕様の初稿に沿って技術検証を行い、仮仕様・優先順位・工数と予備時間を更新する。
- 旧試作の12〜18時間という見積もりは、今回の3投・衝突・回転・カール・スイープを含む仕様にそのまま適用しない。
- 予測誤差、氷の変化に対する追従、ゲームを通して遊べることの検証方法を定める。
- 必須機能と、スイープ助言・多関節アームなどの追加機能を分ける。
- 提出動画・説明資料・再現手順は、新しいゲームの実際の結果に合わせて作成し直す。

## 既存成果物の位置付け

- `src/curling.py` と `src/scene.xml`：1球の直線ショットを検証した旧試作。
- `report/model.json`、`report/evaluation.*`、`report/report_draft.*`と`video/curling_demo.mp4`：旧試作の評価・説明資料・動画。
- `docs/project_plan.md`：旧試作を作成した時点の方針・見積もりの記録。
- 本文書：現在のゲーム要件。基本機能を実装し、統合評価済み。
- `src/poc.py`：既知の氷を使う過去の技術検証用。現在のゲームの入口ではない。
- `src/game.py`、`src/physics.py`、`src/game_scene.xml`、`src/ui.py`、`src/analysis.py`：学習済みAIと逐次補正を接続した現在のゲーム・評価・成果物生成。新しい動画と説明資料は`game_`で始まるファイル。
- `src/predictor.py`、`src/learning_poc.py`、`report/game_straight_*`：直線ショットの学習PoC。観測から摩擦を推定し停止位置を予測する最初の検証。回転・衝突・スイープ・3投の補正を含む完成版のAIではない。
- `src/predictor.py`、`src/curved_poc.py`、`report/game_curved_*`：回転・カール・スイープを含む単独石の学習PoC。独立したMuJoCo世界で停止まで予測する。全石の衝突は次項のPoCで評価する。
- `src/physics.py`の観測復元、`src/predictor.py`の全石予測、`src/collision_poc.py`、`report/game_collision_*`：衝突予測の学習PoC。氷推定モデルを再学習せず、独立した未学習条件で全石の停止誤差・場外・衝突の見落としを評価した。
